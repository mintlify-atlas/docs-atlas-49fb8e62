# User Model

The `UsuarioPOJO` represents a user entity in the e-commerce system. It encapsulates user identification, username, and secure password management through value objects.

## Model Structure

<CodeGroup>
```json Example Response
{
  "id": 12345,
  "usuario": "john.doe@example.com",
  "contrasena": {
    "value": "SecurePass123"
  }
}
```

```java Java Model
public class UsuarioPOJO {
    private Long id;
    private String usuario;
    private ContrasenaVO contrasena;
}
```
</CodeGroup>

## Fields

<ResponseField name="id" type="Long" required>
  Unique identifier for the user.
  
  <Expandable title="Details">
    - Auto-generated by the database
    - Primary key for user records
    - Used for internal references and relationships
  </Expandable>
</ResponseField>

<ResponseField name="usuario" type="String" required>
  Username or email address for the user account.
  
  <Expandable title="Details">
    - Typically used as login identifier
    - Must be unique across the system
    - Can be email address or custom username
  </Expandable>
</ResponseField>

<ResponseField name="contrasena" type="ContrasenaVO" required>
  Password value object with built-in validation and security measures.
  
  <Expandable title="ContrasenaVO Structure">
    <ResponseField name="value" type="String" required>
      The actual password string with strict validation rules.
      
      **Validation Rules:**
      - **Minimum length:** 8 characters
      - **Maximum length:** 64 characters
      - **Complexity:** Must contain at least one letter (A-Z or a-z) and one digit (0-9)
      - **Not null/empty:** Password cannot be null or empty string
      
      **Security Features:**
      - Value object pattern ensures immutability
      - `toString()` method returns `"****"` to prevent accidental password exposure
      - Password updates create new `ContrasenaVO` instances
    </ResponseField>
  </Expandable>
</ResponseField>

## Password Validation

<Note>
  The `ContrasenaVO` value object enforces password security through constructor validation. Any attempt to create a password that doesn't meet requirements will throw an `InvalidPasswordException`.
</Note>

### Validation Rules

The password must satisfy ALL of the following conditions:

| Rule | Requirement | Exception Message |
|------|-------------|------------------|
| **Not Empty** | Password cannot be null or empty | "La contraseña no puede estar vacía" |
| **Minimum Length** | At least 8 characters | "La contraseña debe tener al menos 8 caracteres" |
| **Maximum Length** | No more than 64 characters | "La contraseña no puede superar los 64 caracteres" |
| **Complexity** | At least one letter AND one digit | "La contraseña debe contener al menos una letra y un número" |

### Valid Password Examples

```json
// Valid passwords
"Password1"
"mySecure123"
"Admin2024!"
"Test1234567890"
```

### Invalid Password Examples

```json
// Too short (< 8 characters)
"Pass1"  // InvalidPasswordException

// No digits
"PasswordOnly"  // InvalidPasswordException

// No letters
"12345678"  // InvalidPasswordException

// Empty
""  // InvalidPasswordException

// Too long (> 64 characters)
"ThisPasswordIsWayTooLongAndExceedsTheSixtyFourCharacterLimitSetByTheSystem123"  // InvalidPasswordException
```

## Creating a User

<CodeGroup>
```json Request Body
{
  "usuario": "jane.smith@example.com",
  "contrasena": {
    "value": "StrongPass456"
  }
}
```

```java Java Code
UsuarioPOJO usuario = new UsuarioPOJO();
usuario.setUsuario("jane.smith@example.com");
usuario.setContrasena(new ContrasenaVO("StrongPass456"));
```
</CodeGroup>

## Updating a Password

The `ContrasenaVO` provides an `actualizarContrasena()` method that creates a new password value object:

```java
ContrasenaVO currentPassword = usuario.getContrasena();
ContrasenaVO newPassword = currentPassword.actualizarContrasena("NewSecure789");
usuario.setContrasena(newPassword);
```

<Note>
  Password value objects are immutable. The `actualizarContrasena()` method returns a new `ContrasenaVO` instance rather than modifying the existing one.
</Note>

## Security Considerations

<Warning>
  - Passwords are masked in string representations (`toString()` returns `"****"`)
  - Store password hashes in the database, never plain text values
  - The model enforces validation but does not handle hashing
  - Implement proper password hashing (BCrypt, Argon2) in your service layer
</Warning>
